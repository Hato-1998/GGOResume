GMTK Game Jam 2026 출품작 · 수강신청 모티프 실시간 폴리오미노 퍼즐

개요

수강신청을 모티프로 한 실시간 퍼즐. 필드를 빈틈없이 덮은 폴리오미노 조각이 각각 "정원"을 들고 있고, 정원이 0이 되면 마감되어 사라진다. 학점이 높은 색일수록 빨리 마감되므로 짧은 시간 안에 무엇을 잡을지와 인벤토리를 어떻게 채울지를 동시에 결정해야 한다.

Unity 6 · C# · WebGL 단일 씬. 라운드가 끝나면 인벤토리를 캡처해 LootLocker 리더보드에 점수와 함께 올린다.

기간 2026.07.23 ~ 07.27 (5일) · 팀 2인 · 담당 게임 로직 · 백엔드 · 빌드 파이프라인

담당 작업

  • 게임 로직 구조 설계 — 상태 머신(Title → Countdown → Reveal → Play → Scoring → Result), 시스템 간 직접 참조를 없앤 정적 이벤트 허브, ScriptableObject 단일 파라미터 소스
  • 필드 생성기 — 폴리오미노 덱만으로 12×10(120셀) 필드를 빈칸 없이 덮는 반복 백트래킹 솔버, 실패 시 2단 폴백
  • 수강신청 정원 시스템 — 조각별 독립 난수 스트림으로 정원 감소·취소 부활 처리, 색별 주기 분리로 고학점 과목이 먼저 마감
  • 드래그&드롭 배치 — uGUI EventSystem 드래그, 배치 고스트 프리뷰, 우클릭으로 필드 원위치 회수
  • 채점 — 색 점수와 인벤토리 셀 모디파이어를 규칙 인터페이스로 분리
  • 온라인 리더보드 — LootLocker 세션·점수 제출·인벤토리 스크린샷 썸네일 업로드/조회
  • WebGL 빌드 파이프라인 — 에디터/배치 빌드 진입점, 플랫폼 설정 강제

게임 스펙

필드
12 × 10 = 120셀. 매 라운드 빈틈없이 덮인 상태로 시작한다
조각 풀
7종(I·J·L·O·S·T·Z) 전부 4셀 테트로미노 → 한 판 30조각
색상
7색, 점수 10·9·8·7·6·5·4. 고학점 색일수록 정원이 적고 감소 주기가 짧다
라운드
플레이 20초 · 시작 전 카운트다운 5초

필드 생성기 설계

3단 구조 — 완전 타일링보다 "항상 종료"를 먼저 보장

  • 실현가능성 게이트 — 풀에 있는 조각 셀 수의 최대공약수로 전체 셀 수가 나누어떨어지는지 O(1)로 검사. 실패하면 솔버를 아예 돌리지 않고 그리디로 직행한다
  • 반복 백트래킹 솔버 — List<Frame>을 스택으로 쓰는 비재귀 탐색. Frame이 struct라 in-place로 갱신된다. 분기 휴리스틱은 first-empty-cell — row-major 첫 빈칸을 반드시 덮는 후보만 생성해 진행을 보장한다(MRV는 쓰지 않았다)
  • 그리디 폴백 — 백트래킹이 없다. 맞는 조각이 없으면 그 칸을 영구 빈칸으로 표시하고 계속 진행해, 어떤 조각 풀에서도 종료가 보장된다

예산 3종

시간 예산
2,000ms — C# 기본값 1,000ms를 ScriptableObject에서 덮어씀
노드 예산
480,000 = max(셀 수 120 × 4,000, 하한 200,000)
재시도 상한
10 (첫 시도 포함 총 11회)

코루틴 슬라이스 — 두 경로가 다른 기준을 쓴다

그리디는 배치 개수마다 yield하지만, 솔버는 경과 시간 4ms마다 yield한다. 애초엔 두 경로가 같은 값을 썼는데, "프레임당 조각 수"로 튜닝된 값이 솔버에서 "프레임당 탐색 노드 수"로 재사용되고 있었다. 노드 개수로 양보하면 프레임당 실제 탐색량이 플레이어의 프레임레이트를 따라가고, 그러면 시간 예산 2,000ms가 "실제 탐색에 쓴 시간"을 뜻하지 않게 된다 — 느린 기기에서 솔버가 더 일찍 포기하고 다른 판이 나온다. 예산이 무엇을 재는 값인지 지키기 위해 솔버 쪽만 실경과 시간 기준으로 분리했다.

폴백 2계층

  • 계층 A · 솔버 영구 비활성화 — 솔버가 예산을 넘겨 실패하면 이후 모든 재시도에서 솔버를 끈다. 예산을 넘기는 시드는 재시도해도 대체로 다시 넘기기 때문에, 그대로 두면 재시작 후 카운트다운이 수십 초 멈춘다
  • 계층 B · 직전 성공 레이아웃 재사용 — 결과가 불완전하면 마지막으로 성공한 레이아웃을 그대로 두고 색만 다시 배분한다. 판이 깨진 채로 라운드가 시작되지 않는다

색상 균등 배분

확률 가중이 아니라 정확한 개수를 담은 가방을 Fisher-Yates로 섞는 방식이라, 색별 개수 차이가 항상 1 이하로 보장된다. 30조각 ÷ 7색이면 5색은 4개, 2색은 5개. 확률 가중이면 한 판에서 특정 색이 몰려 점수 상한이 시드마다 크게 흔들리기 때문에 배제했다. (균등 제약은 색상 기준이며, 블록 종류에는 걸려 있지 않다.)

트러블슈팅

1. WebGL 빌드가 첫 프레임에 죽던 부팅 크래시

증상
배포 빌드에서만 Uncaught exception from main loop → Halting program. 아무것도 렌더링되기 전에 사망. 에디터와 배치 빌드는 정상
원인
트윈 라이브러리의 이징 평가 함수가 Burst Direct Call 폴백에서 자기 자신의 역방향 래퍼를 호출 → 무한 재귀. 타이틀 트윈이 첫 프레임에 이징을 평가하는 순간 스택 오버플로. 패키지는 며칠 전 도입됐지만 씬에 트윈이 처음 배치된 건 크래시 당일 — 설치와 실행은 다름
검증
예외 지원 설정을 범인으로 오진해 커밋까지 감. 심볼 포함 프로브 빌드를 따로 구워 스택에서 함수 이름을 확보하고 원인 확정. Burst 활성 2/2회 재현, 비활성 0회
수정
WebGL 타깃 Burst AOT 비활성. 조용히 되돌아갈 수 있는 설정이라 릴리즈 빌드 진입점이 매번 강제
결과
콘솔 에러 0, 렌더 루프 진입. wasm 54.5MB → 54.3MB. 오진했던 커밋 메시지를 바로잡는 정정 커밋 추가

2. 리더보드를 몇 번 열면 점수 제출까지 막힘

증상
리더보드 반복 열람 후 백엔드 요청이 몇 분간 전부 실패. 그 라운드 점수가 통째로 소실
원인
썸네일 URL 해석이 행마다 파일 목록 API를 호출 — 50행 + 본인 카드 = 51요청. 서명 URL이 CORS로 막혀 스프라이트 캐시가 채워지지 않으니 열 때마다 전체 팬아웃 반복. SDK 요청 수 제한에 걸리는 순간 점수 제출을 포함한 모든 요청이 하드 실패
검증
열람 1회당 실제 발생 요청 수를 세어 SDK 리미터 한계치와 대조. 캐시가 채워지지 않는 이유(CORS 차단)를 응답에서 확인
수정
해석 결과를 캐시. "썸네일 없음"인 빈 결과까지 캐시해야 재조회가 멈춘다. 다운로드는 대기자 목록을 두어 한 번만 받고 그 사이 요청한 모든 행에 배분
결과
재열람 51요청 → 약 2요청. 리미터 연쇄 실패 소멸. 같은 경로의 텍스처 누수·표시 중 해제 문제도 함께 정리

3. 필드에 빈칸이 남던 생성기

증상
폴리오미노로 필드를 채우면 군데군데 빈칸. 의도한 "빈틈없이 덮인 판"이 나오지 않음
원인
첫 빈 칸을 순서대로 메우는 그리디 방식. 한 번 dead-end에 빠지면 되돌아갈 수단이 없음
검증
EditMode 유닛 테스트로 고정 — 테스트 보드(12×8, 96칸)에서 24조각 미커버 0, 같은 시드는 같은 레이아웃(색 포함), 해가 존재하지 않는 조각 풀에서는 폴백 동작
수정
명시적 스택 기반 반복 백트래킹 솔버로 교체 — 완전 피복(exact cover) 문제를 재귀 없이 푼다. 코루틴 yield와 공존해야 해 재귀는 사용 불가. 조각 크기의 최대공약수가 필드 넓이를 나누지 못하면 탐색 없이 즉시 폴백, 탐색 예산 초과 시 그리디로 내려가 항상 종료
결과
빈칸 0 완전 타일링. yield가 난수를 소비하지 않도록 설계해 결정론도 유지

그 외 처리한 이슈

  • 우클릭이 브라우저 컨텍스트 메뉴를 띄움 — 컨텍스트 메뉴를 막는 코드는 커스텀 WebGL 템플릿 안에만 있는데 템플릿이 선택돼 있지 않았음. 직전 인수인계 문서 기록과 실제가 달랐고, 이후로는 빌드 진입점이 설정을 단언
  • 닉네임이 이전 이름으로 되돌아감 — 세션 재동기화가 매 실행마다 옛 이름을 서버로 push. 계측 로그로 옛 이름 쓰기가 0.08초 앞서 완료되는 것을 실측한 뒤, 재동기화를 실패·보류 시에만 발화하도록 변경해 경합 구간 제거
  • 동시 드래그로 조각 영구 유실 — UI 입력 모듈이 버튼마다 독립된 드래그 상태 머신을 돌려, 좌클릭 드래그 중 우클릭 드래그가 대상을 덮어씀. 좌버튼·재진입 가드 + 드래그 시작 포인터에 고정
  • 가장자리를 잡으면 커서와 도형이 어긋남 — 앵커를 셀 단위로 반올림했고 기준 좌표가 드래그 임계값만큼 움직인 뒤의 위치였음. 연속 좌표 + "처음 누른 지점" 기준으로 교체
  • 마지막 배치가 썸네일에서 누락 — 드래그 정리 전에 종료 판정이 동기 연쇄로 돌아 조각을 비활성화. 썸네일은 같은 프레임 끝에 찍힘. 상태 확정·드래그 정리를 연쇄보다 앞으로
  • 종료 시 유령 오브젝트 재생성 — 싱글턴 지연 생성이 teardown 중에도 동작. OnApplicationQuit이 모든 OnDestroy보다 먼저 실행되는 것을 이용해 루트에서 차단
  • 제출 실패 시 기록 소실 / 낡은 응답이 방금 낸 점수를 덮어씀 — 제출 전 로컬에 적어두고 다음 실행에 재제출, 요청에는 세대 토큰을 붙여 늦게 착지한 응답을 폐기

그 외 설계 판단

  • 드래그 레이어를 씬이 아니라 런타임에 구성 — 중첩 Canvas + overrideSorting. 씬의 sibling 순서에만 의존하면 이미 배치된 조각이나 그리드 배경이 드래그 중인 조각을 덮는다. overrideSorting은 부모 Canvas 아래일 때만 유효해 씬에 미리 구워둘 수 없었다
  • 배치 확정 로직을 포인터 이벤트에서 분리 — TryPlaceInInventory/ReturnToField로 떼어내, 드래그 시뮬레이션 없이 배치 규칙만 단위 테스트할 수 있게 함
  • 채점을 순수 정적 함수로 — ScoreManager.Compute가 ScriptableObject·씬 오브젝트에 의존하지 않아 EditMode에서 그대로 검증된다. 씬 상태 수집은 별도 경로로 분리
  • 썸네일은 URL이 아니라 파일 id를 저장 — LootLocker가 돌려주는 url이 만료되는 서명 URL임을 확인하고, 점수 metadata에는 파일 id만 넣은 뒤 표시 시점에 재서명 URL을 재발급받는 구조로 전환

알려진 한계

  • 첫 판에는 계층 B 폴백이 걸리지 않는다. 재사용할 "직전 성공 레이아웃"이 아직 없기 때문. "항상 완전 타일링"은 2번째 판부터 성립한다
  • 시간 분할 솔버 경로는 자동 테스트가 덮지 못한다. EditMode 테스트는 전부 동기 경로(슬라이스 0)를 호출한다. 코루틴으로 쪼개진 실제 실행 경로는 수동 확인에 의존한다
  • 생성기는 시드 결정론적이지만 게임은 그 결정론을 쓰지 않는다. 시드 모드가 Random이라 매 실행 판이 달라진다. 결정론은 회귀 테스트·재현용으로만 남아 있다
